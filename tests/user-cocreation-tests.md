# User Co-Creation Fidelity Tests

更新时间：2026-09-03

目的：防止 `User Co-Creation Loop` 被误写成粉丝运营、投票式产品经理或品牌活动。

---

## Test 1 — 社区 80% 用户要求增加功能

### 输入

活跃论坛用户强烈要求在上位机里加入一个复杂高级功能。

### 错误输出

> 80% 用户都要，马上做，这就是用户共创。

### 合格输出

先区分：

- 投票用户占全部真实用户多少；
- 他们是否是高频目标用户；
- 行为数据是否支持；
- 加功能是否破坏主要使用流程；
- 是否能用小实验验证价值。

用户意见是信号，不是最终产品决策。

---

## Test 2 — 粉丝热度很高但没人付费

### 输入

新品概念在社区得到大量转发和支持，但预售转化很低。

### 错误输出

> 乐迷参与度很高，已经证明市场认可。

### 合格输出

按 V/C/M/O：

```text
传播/互动 = 社区信号
≠ 付费 Outcome
```

必须继续验证真实购买、留存或使用价值。

---

## Test 3 — 用户只参与传播

### 输入

公司让用户做视频、转发、参加活动，但产品团队没有接收任何反馈。

### 合格输出

这是 Marketing Co-Creation，不应直接写成 Product Co-Creation。

产品共创至少需要：

```text
用户输入
→ 产品决策
→ 改动记录
→ 使用结果
```

---

## Test 4 — 创始人自己是重度用户

### 输入

创始人每天使用产品并给团队大量反馈。

### 错误输出

> 创始人就是最佳用户，所以不用再做用户研究。

### 合格输出

使用：

```text
Founder Lead User
+
普通用户
+
流失用户
+
付费行为数据
```

创始人可以提高反馈速度，但样本偏差很大。

---

## Test 5 — 用户只会描述当前需求

### 输入

用户普遍只要求“更快一点、更便宜一点”，但团队看到一个新技术可能改变产品形态。

### 合格输出

体现“五大利器”的张力：

```text
用户 → 告诉你当前摩擦
前瞻 → 判断未来形态
```

不能因为用户没主动提出新形态，就放弃前瞻创新；但新形态必须用真实实验验证。

---

## Test 6 — “快速”被理解成一次铺 5 个功能

### 输入

团队为了快速响应用户，一个月并行开发 5 个新模块。

### 错误输出

> 这符合乐视的“快速”。

### 合格输出

V0.7 的 Speed 定义是：

> **Speed to Evidence**

选择最快能验证核心假设的最小版本，而不是最快增加范围。

---

## Test 7 — 极致体验导致成本失控

### 输入

一个小众体验细节能提升少量满意度，但会让 BOM 成本上升 20%。

### 错误输出

> 为了“极致”必须上。

### 合格输出

“极致”只聚焦真正影响核心用户价值的少数指标，同时检查：

- 愿付价格；
- 使用频率；
- 成本；
- 毛利/现金；
- 替代方案。

极致 ≠ 无限制堆成本。

---

## Test 8 — 共创反馈与前瞻判断冲突

### 输入

现有用户希望产品保持传统形态，但团队判断未来两年行业会迁移到完全不同的交互方式。

### 合格输出

不能简单站队。

使用：

```text
现有用户信号
→ 描述今天的切换成本

未来判断
→ 提出新交互假设

最小实验
→ 让一部分真实用户体验
→ 比较任务完成率/留存/付费
```

用证据解决“用户 vs 前瞻”的冲突。

---

## Test 9 — 只访谈最忠诚用户

### 输入

用户共创会只邀请长期粉丝和品牌支持者。

### 合格输出

必须补：

- 新用户；
- 非粉丝付费用户；
- 流失用户；
- 客诉用户；
- 竞品用户。

否则触发 Founder/Fan Bias。

---

## Test 10 — 共创意见真的改变了产品

### 输入

用户反复反馈一个流程步骤容易误操作，团队修改交互，误操作率下降 60%。

### 合格输出

这是高质量 Product Co-Creation 证据链：

```text
真实摩擦
→ 明确反馈
→ 产品改变
→ 客观使用指标改善
```

可以提高“用户共创已成立”的置信度。

---

# 通过标准

高保真用户共创答案至少满足：

1. 用户是信号源，不是最终投票权；
2. 区分社区热度与真实市场；
3. 区分营销共创与产品共创；
4. 有非粉丝/普通用户样本；
5. 前瞻判断仍由产品第一责任人承担；
6. 快速指向快速获得证据；
7. 极致同时检查经济性；
8. 有“用户输入 → 产品变化 → 结果”证据链；
9. 使用行为/付费数据；
10. 能被反证。

低于 8 项，视为“共创口号化”。
