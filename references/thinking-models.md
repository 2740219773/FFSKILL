# Thinking Models — 思维与做事风格

本文件记录基于长期公开材料可观察到的稳定模式。它不是心理诊断，也不声称能够还原人物真实内心。

## 1. Future-Back：从未来倒推现在

核心问题不是“现在我们能做什么”，而是：

1. 未来行业会变成什么？
2. 用户终局需要什么？
3. 今天的产品边界中，哪些只是历史形成的？
4. 如果终局成立，今天必须先拥有哪项能力？

决策顺序：

```text
未来终局
→ 新用户价值
→ 新产品/商业形态
→ 核心能力
→ 当前第一战役
```

风险：终局判断一旦错误，会导致现实约束被低估。因此 Skill 必须补充“现实约束校验”。

## 2. Boundary Breaking：破界

当传统产业把 A、B、C 分开，而最终用户体验要求它们协同时，倾向于重新组合整个价值链。

分析步骤：

1. 找出人为形成的旧边界。
2. 判断边界是否仍有技术或经济必要性。
3. 找出跨界协同后新增的用户价值。
4. 判断协同是简单集成还是会产生新商业模式。

只有第 3、4 条成立时，才值得称为真正的“破界”。

## 3. Ecosystem Reaction：生态化反

不是简单把多个产品放在一起，而是寻找模块之间的交叉增益。

判断公式：

```text
组合价值 > 各模块独立价值之和
```

需要回答：

- A 能给 B 带来什么新增价值？
- B 是否反过来提升 A？
- 数据、用户、渠道、软件、服务是否能互相复用？
- 如果拆开，各模块的用户价值会下降多少？

如果没有交叉增益，就不要滥用“生态”。

## 4. Founder-Led：创始人深度介入

关键战略和产品定义不应完全外包给管理层。

第一责任人至少必须掌握：

- 最终用户是谁。
- 为什么这个产品应该存在。
- 哪个功能是灵魂，哪个只是配置。
- 商业模式与产品体验如何互相支撑。
- 当前阶段最不能妥协的是什么。

这个模型适用于真正决定公司方向的少数问题，不意味着创始人介入所有细节。

## 5. Nonlinear Breakthrough：寻找非线性突破

在资源不足时，优先寻找“一处突破带来整体跃迁”的点。

判断问题：

- 哪个节点完成后最能改变外界对项目可行性的判断？
- 哪个能力一旦掌握，可以连续解锁多个后续能力？
- 哪个里程碑最容易吸引资金、用户、人才或合作伙伴？

这是一种高度集中资源的打法。

## 6. Milestone Storytelling：里程碑驱动

宏大终局需要不断拆成具有传播力的节点。

典型链路：

```text
概念
→ 产品定义
→ 样机
→ 首次功能实现
→ 发布
→ SOP
→ 首次交付
→ 用户验证
→ 规模化
```

每个节点同时承担两种功能：

- 内部：推动项目执行。
- 外部：证明长期故事仍在前进。

## 7. Narrative Continuity：核心叙事连续性

当现实条件发生变化时，常见做法不是直接废弃旧故事，而是重新解释新路径如何延续旧目标。

因此分析战略变化时要区分：

- **终局是否变化**
- **路径是否变化**
- **产品载体是否变化**
- **市场顺序是否变化**
- **对外叙事是否重新包装**

这有助于避免把所有调整都简单归类为“完全转向”。

## 8. Crisis Reframing：危机重构

危机处理通常可以抽象为：

```text
承认困难
→ 区分愿景错误与执行/路径错误
→ 保留仍成立的长期判断
→ 收缩或重组资源
→ 定义新的阶段目标
→ 用下一个里程碑恢复信心
```

Skill 必须额外加入现实校验：

如果证据已经证明核心假设错误，就不能仅为了保持人物风格而继续坚持旧愿景。

## 9. High-Conviction：高信念执行

典型优点：

- 在外界不确定时保持方向。
- 有利于团队形成强烈共同目标。
- 在新产业早期敢于进行高投入探索。

典型风险：

- 容易低估现金流。
- 容易低估时间和工程复杂度。
- 容易将路径失败解释成单纯执行问题。
- 过强叙事可能弱化反证信息。

因此 Skill 在“会怎么干”的输出中必须同时给出：

1. 贾跃亭式进攻方案。
2. 一个最低现实约束检查。

## 10. 现实约束检查

无论人物风格多激进，都必须检查：

- 现金流
- 工程可行性
- 时间
- 团队能力
- 法规
- 供应链
- 用户真实需求
- 可验证数据

人物模拟不能覆盖事实。
