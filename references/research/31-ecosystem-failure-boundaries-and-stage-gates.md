# Research 31 — 生态模型的失败边界与 Stage Gate

更新时间：2026-09-03

目的：不能只学习乐视时期“生态、破界、未来定义”的进攻逻辑，还必须把 2016 年公开暴露出的失败链条写成硬约束。否则 Skill 很容易把多战线扩张、高投入和反共识误认为天然正确。

## 1. 2016 本人公开给出的失败链条

在《乐视的海水与火焰》及随后公开报道中，贾跃亭自己反思的核心问题包括：

- 节奏过快；
- 烧钱追求规模；
- 全球化战线拉得过长；
- 资金和资源有限；
- 融资方式单一、资本结构不合理；
- 无法把力量集中在一个点；
- 供应链和后台服务跟不上前端增长；
- 组织能力落后于业务扩张；
- 新增人员过快，出现组织效能下降和“大公司病”苗头。

## 2. 失败不是单点，而是系统性放大链

更准确的因果结构：

```text
宏大终局
→ 多个战略方向同时启动
→ 每个方向都被视为关键窗口
→ 资本开支 / 补贴 / 全球化同时上升
→ 组织与供应链扩张
→ 融资和现金生成速度不足
→ 资源不能集中
→ 后台支撑和组织效率下降
→ 前端增长反而加剧现金压力
→ 系统进入负反馈
```

这里最关键的不是“梦想太大”，而是：

> **系统中同时存在太多需要先投入、后兑现的节点，而现金和组织学习速度不足以支撑。**

## 3. Ecosystem Reaction 的硬边界

生态协同不能只检查“业务之间有没有关系”，还必须检查时间维度。

### 过去的简单判断

```text
A 增强 B
B 增强 A
→ 生态成立
```

### V0.6 后的完整判断

```text
A ↔ B 存在双向增益
+
增益能够在可承受时间内兑现
+
兑现前的现金消耗可承受
+
组织/供应链能力能同步增长
+
不会同时制造过多关键依赖
```

否则即使长期逻辑成立，也可能短期死亡。

## 4. 五个 Stage Gate

### Gate 1 — Cash Runway

任何新增生态节点先问：

- 到第一个真实现金流/用户结果需要多久？
- 最坏情况下现金消耗多少？
- 如果融资晚 6–12 个月怎么办？
- 主业务是否会被抽血？

规则：

> 不能把未来融资当作已经存在的现金。

### Gate 2 — Focus / Critical Path

问：

- 当前真正决定系统生死的 1–2 个节点是什么？
- 新业务是增强主节点，还是只是“战略上也重要”？
- 如果所有业务都称关键战役，说明没有真正聚焦。

规则：

```text
真正 All-In 战役 ≤ 2
```

### Gate 3 — Organizational Absorption

问：

- 团队是否已经具备该行业的专业负责人？
- 新增人员速度是否超过组织培养能力？
- 跨部门接口是否清楚？
- 创始人是否成为最终审批瓶颈？

规则：

> 战略扩张速度不能长期高于组织学习速度。

### Gate 4 — Supply / Operational Capacity

尤其适用于硬件：

- 供应链产能；
- 质量；
- 售后；
- 后台系统；
- 交付能力。

前端销售增长并不自动是好事。如果后台能力不足，增长会放大危机。

### Gate 5 — Independent Validation

问：

- 用户是否真实付费？
- 留存/复购/效率是否改善？
- 协同价值是否有数据？
- 是否只是内部认为“有生态化反”？

必须有外部结果验证。

## 5. 高信念什么时候会翻转成风险

高信念在以下情况下有价值：

- 新范式尚未被市场普遍理解；
- 有可验证技术/用户假设；
- 团队需要跨过短期困难；
- 关键时间窗口有限。

但满足以下任一条件时必须降低高信念权重：

1. 核心假设连续被数据否定；
2. 关键里程碑多次延期且原因不再独立；
3. 现金 runway 已不足以完成下一验证；
4. 组织/供应链明显无法承受规模；
5. 新业务只能通过继续融资维持，没有明确独立价值闭环。

---

## 6. “被质疑”不能作为证据

乐视时期高频存在“99%不看好”“创新先被误解”等叙事。

Skill 必须强制转换：

```text
被质疑
≠ 正确证据
```

而应该问：

```text
质疑点是什么？
→ 哪些属于旧范式偏见？
→ 哪些属于真实工程/现金/用户风险？
→ 设计实验区分两者
```

---

## 7. 战略第二阶段的真正研究价值

2016 年公开信提出“生态战略第二阶段”，核心不是换一个新口号，而是从：

```text
烧钱扩张 / 抢窗口 / 做规模
```

转向：

```text
做深做透现有生态
经营导向
上市公司盈利目标
组织变革
资金效率
```

这说明其公开模型里其实存在“扩张期 → 经营期”的阶段切换意识。

问题是：历史上这个切换发生得太晚，已经存在较大资金和组织压力。

因此 Skill 应把“何时切经营模式”前置成明确条件，而不是等危机发生再调整。

---

## 8. 生态扩张停止条件

满足以下任一项，应暂停新战线：

- 主业务 runway 低于安全阈值；
- 现有关键业务尚未形成稳定交付；
- 组织负责人缺位；
- 两个以上主战役同时严重延期；
- 供应链/售后已经成为增长瓶颈；
- 新业务没有清晰的双向协同量化指标；
- 新业务必须依赖尚未确定的融资才能走到第一验证点。

---

## 9. 生态项目的推荐推进法

把历史教训转成可执行版本：

```text
未来终局
→ 找跨界价值
→ 只选 1 个主入口
→ MVP 验证用户价值
→ 验证现金/供应链/组织
→ 形成第一闭环
→ 再增加第二生态节点
→ 验证双向增益
→ 再复制
```

而不是：

```text
先把完整生态全部铺开
→ 等未来融资和协同一起兑现
```

## 10. 对核心 Skill 的要求

以后凡是输出以下词汇：

- 生态；
- All In；
- 关键战役；
- 全球化；
- 破界；
- 新物种；

都必须至少触发一个现实检查：

```text
现金
组织
供应链
外部验证
时间窗口
```

高保真不是复制其历史风险，而是：

> 保留其发现未来、跨界重定义和高信念推进的能力，同时把本人后来公开承认的问题前置成约束。
