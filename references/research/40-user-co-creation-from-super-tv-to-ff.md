# Research 40 — 用户共创：从超级电视 CP2C 到 FF Developer Co-Creation

更新时间：2026-09-03

目的：验证“共创共享 / Developer Co-Creation”究竟是近年 FF 新叙事，还是贾跃亭长期产品哲学的延续。

结论：公开资料支持一条至少跨 2013–2023 的连续线：

```text
用户不是交易终点
→ 用户参与产品定义
→ 用户反馈进入研发迭代
→ 使用行为形成数据
→ 产品/内容/服务继续进化
→ 用户参与传播与品牌
→ 再回到下一轮产品定义
```

这比“重视用户”更具体，属于一个可独立建模的长期行为模式。

---

# 1. 2013：CP2C 已经是全流程用户参与模型

2013-04 乐视TV公开提出 CP2C（Customer Planning to Customer）。当期报道记录的流程不是普通“听用户意见”，而是：

```text
产品设计
→ 研发
→ 传播
→ 销售
→ 售后
→ 运营
→ 再循环到产品设计
```

用户被设定为每个环节的参与者。

来源：
- 新浪科技/中证网：https://tech.sina.com.cn/e/2013-04-08/15558218007.shtml

核心口号之一：

> 千万人不满、千万人参与、千万人研发、千万人使用、千万人传播。

这里最值得 Skill 学的不是口号，而是**闭环结构**。

---

# 2. 2013 超级电视：产品不是公司单方面“造出来”的

2013-05 超级电视发布前内部邮件中，贾跃亭直接把产品创造权上升到用户：

```text
用户痛点
→ 用户参与
→ 聚合用户智慧
→ 产品定义
→ 产品持续成长
```

并明确表达“不是公司单方面造出超级电视，而是用户创造超级电视”的逻辑。

来源：
- 新浪科技：https://tech.sina.com.cn/i/2013-05-02/13388298361.shtml

这说明用户在其早期系统中的角色已经不是：

```text
消费者
```

而是：

```text
需求信号
+ 产品参与者
+ 使用数据来源
+ 传播节点
```

---

# 3. 2013：Founder Lead User 与直接用户反馈

同期采访还记录：

- 互联网公司能随时与用户沟通和反馈；
- 贾跃亭本人会通过微博/微信直接接收消费者反馈；
- 会关注遥控器、交互等细节；
- 产品体验要靠实际反馈，而不是公司内部口号。

来源：
- 新浪科技：https://tech.sina.com.cn/e/2013-06-09/12138429261.shtml

这与核心 Skill 里的 Founder Lead User 可以形成更完整的两层结构：

```text
创始人亲自体验
+
大量真实用户持续反馈
```

不能只有前者。

---

# 4. 2014：用户被放到“五大利器”第一位

2013–2014 多个近同期材料记录贾跃亭总结互联网模式的“五大利器”：

```text
用户
前瞻
快速
协同
极致
```

其中用户被明确放在第一位。

来源：
- 新浪科技：https://tech.sina.com.cn/i/2014-01-27/11589131647.shtml
- 中证网：https://www.cs.com.cn/ssgs/gsxl/201401/t20140127_4295783_1.html
- 2014 员工信：https://tech.cnr.cn/techhlw/201401/t20140122_514718944.shtml

更关键的是，公开材料描述的闭环是：

```text
用户参与
→ 了解需求/痛点
→ 前瞻判断未来机会
→ 快速落地
→ 内部 + 外部协同
→ 极致体验
→ 再次用户参与
```

这已经是一套完整的产品迭代循环。

---

# 5. 2014：“用户拥有产品和品牌”

当期采访中，贾跃亭进一步把用户角色从“参与者”推向“产品和品牌共同拥有者”的表达。

这类说法的高保真抽象不应是法律意义上的所有权，而应理解为：

- 产品方向由用户持续反馈影响；
- 品牌传播由社区成员参与；
- 用户关系长期运营，而非一次交易结束；
- 社区价值与产品价值互相反馈。

Skill 不应把这类历史修辞直接转换成真实股权/产权事实。

---

# 6. 2015：超级手机继续沿用“用户参与—产品成长”

2015-05 致乐迷家书里，贾跃亭再次使用：

```text
千万人不满
→ 千万人参与
→ 千万人受益
```

并明确把乐迷在微博、社区、朋友圈中的反馈和参与，连接到产品持续成长。

来源：
- 新浪科技：https://tech.sina.com.cn/i/2015-05-17/doc-iawzuney5713363.shtml

同年手机相关公开材料还强调：

> 手机卖给用户，不是用户关系结束，而是服务关系真正开始。

来源：
- 人民网通信频道：https://tc.people.com.cn/n/2015/0520/c183008-27026958.html

因此手机时代延续的是同一模型：

```text
硬件交付
≠ 用户关系终点
```

而是：

```text
硬件交付
→ 内容/服务/系统更新
→ 用户反馈
→ 下一轮产品/服务
```

# 7. 2023：FF 把长期用户共创正式产品化/制度化

2023 年 FF 官方材料重新高频使用 User Co-Creation / Developer Co-Creation。

## 7.1 User Co-Creation

FF 9 周年活动明确建立用户共创社区活动。

来源：
- FF 官方：https://www.ff.com/us/user-cocreation/

## 7.2 Mission Farad

2023-05 FF 发布 Mission Farad，试图把用户共创进一步结构化为：

- 开源共创技术平台；
- 共创/共享商业模式；
- 合伙治理结构；
- 产品组合。

来源：
- FF 官方：https://www.ff.com/us/press-room/FF-announces-user-based-co-creation-mission-farad/

## 7.3 Owner / Developer Co-Creation

2023-06 起，FF 把首批车主进一步定义为 Owner Developer Co-Creation 参与者。

来源：
- FF 官方：https://www.ff.com/us/press-room/FF-launches-the-FF91-owner-developer-cocreation-plan/

## 7.4 三阶段反馈

2023-10 FF 官方材料还具体描述贾跃亭本人交付后的三阶段 Co-Creation：

```text
交付日
→ 一个月内组织产品共创会议并反馈体验
→ 一个月后继续通过日常驾驶提供产品反馈
→ 给下一代产品提出建议
```

来源：
- FF IR：https://investors.ff.com/news-releases/news-release-details/faraday-future-will-host-another-delivery-co-creation-day-yt-jia

这比单纯“社区营销”更接近真实产品反馈机制。

# 8. 跨十年的稳定模型

可以压缩为：

```text
2013 CP2C
产品全流程用户参与

↓

2014 五大利器
用户成为整个互联网产品循环的第一环

↓

2015 乐迷
用户参与产品成长 + 长期服务关系

↓

2023 FF Developer Co-Creation
车主/开发者参与反馈、传播、产品迭代和下一代产品
```

因此较高置信度的稳定模式是：

> **用户不仅是购买者，而被长期定义为产品信号源、共同迭代者、社区传播节点和持续服务关系的一部分。**

---

# 9. 可用于 Skill 的 User Co-Creation Loop

```text
真实用户痛点
→ 收集参与/行为信号
→ 区分高频需求与噪声
→ 产品团队形成新定义
→ 小版本/实验快速上线
→ 使用数据验证
→ 社区反馈
→ 产品继续进化
```

其中“用户参与”不能替代前瞻判断。

历史五大利器本身就是：

```text
用户
+
前瞻
```

也就是说：

> 既不能闭门造车，也不能把产品经理退化成用户投票统计员。

---

# 10. 四个必须防范的共创幻觉

## 10.1 Vocal Minority Bias

最活跃的社区用户不一定代表大市场。

制动器：

```text
社区意见
+
行为数据
+
普通用户样本
+
付费结果
```

## 10.2 Community ≠ Market

粉丝热度不能自动证明市场需求。

论坛点赞、预热传播、活动参与与真实购买必须分开。

## 10.3 Marketing Co-Creation ≠ Product Co-Creation

如果用户只参与：

- 转发；
- 活动；
- 品牌宣传；

但无法影响任何产品决策，就不能把它当强产品共创证据。

高质量共创至少要记录：

```text
用户提出什么
→ 产品是否改变
→ 为什么改变/不改变
→ 改后结果如何
```

## 10.4 Founder/Fan Bias

强创始人品牌容易让粉丝反馈偏向支持。

必须主动寻找：

- 非粉丝用户；
- 流失用户；
- 付费但不活跃用户；
- 客诉用户。

---

# 11. 与 Founder Lead User 的组合

高保真实现不是：

```text
创始人自己觉得好
```

也不是：

```text
用户投票最多就做
```

而是：

```text
Founder Lead User
+
用户共创信号
+
行为数据
+
外部市场验证
```

第一责任人负责解释未来和做取舍，用户负责不断提供现实摩擦和使用信号。

---

# 12. 一句话模型

> **产品交付不是用户关系的结束，而是持续共创闭环的开始；但真正的共创必须能影响产品决策，并最终由真实使用和付费结果验证。**
