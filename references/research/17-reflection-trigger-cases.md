# Research 17 — Reflection / 纠偏机制触发案例

更新时间：2026-09-03

目的：验证“反思/纠偏”到底是不是贾跃亭现代 Weekly Report 的固定口癖，还是只有遇到真实执行问题时才被触发。

结论：当前证据更支持后者。

## Case 1 — 2025-05-26：Weekly Report #004

一手来源：

https://investors.ff.com/news-releases/news-release-details/faraday-future-founder-and-co-ceo-yt-jia-shares-weekly-1/

核心表达结构：

```text
每周记录
→ 迫使自己反思
→ 保持 problem-solving
→ outcome driven
→ 展示真实进展
→ 规划下一周
```

研究价值：

这是“为什么做周报”的方法论表达，说明 Reflection 被设计成执行反馈机制的一部分。

但它并不等于以后每一期都必须写“我反思了”。

## Case 2 — 2025-11-09：Weekly Report #028

一手来源：

https://investors.ff.com/news-releases/news-release-details/faraday-future-founder-and-co-ceo-yt-jia-shares-weekly-18/

当期明确出现：

`Issues, Reflections & Solutions`

触发原因之一是外部平台错误展示 Earnings Call 日期，而公司没有及时纠正，造成误解。

典型结构：

```text
具体错误
→ 说明造成的影响
→ 复盘内部机制
→ 给出修正动作
```

研究意义：

Reflection 与**可识别的问题**直接绑定。

## Case 3 — 2026-02-16：市场表现 / Robotics / AIxC 纠偏

一手来源：

https://investors.ff.com/node/13721/pdf

官方摘要明确表示：

- 在进行彻底内部反思和复盘之后；
- FF 将推出 EAI Robotics 的 correction and improvement plan；
- 同时建议 AIxC 做重大变化；
- 重新加强围绕 FF 的战略与运营聚焦；
- 具体方案将在下一周 Weekly Report 给出。

结构非常典型：

```text
外部/经营压力
→ internal reflection and review
→ correction / improvement plan
→ strategic focus
→ 下一周给出细节
```

这是目前最强的“Reflection 是危机/偏差触发模块”证据之一。

## Case 4 — 2026-03-29：周报机制本身升级

一手来源：

https://investors.ff.com/news-releases/news-release-details/faraday-future-founder-and-co-ceo-yt-jia-shares-weekly-34/

在 Weekly Report 接近运行一年时，贾跃亭公开回顾：周报记录了公司不同阶段的真实状态、判断、选择和 reflections，并提出下一阶段计划升级周报、征求投资者反馈。

这里 Reflection 更接近**管理机制复盘**，而不是情绪化自我批评。

# 触发规则

综合以上案例，Skill 应按以下逻辑运行：

```text
如果没有明确偏差/失败/误解/机制问题
→ 不强制 Reflection

如果出现：
- 延期
- 沟通错误
- 市场/股价压力需要回应
- 战略分散质疑
- 产品/业务执行低于预期
- 管理机制本身需要升级

→ 激活 Reflection
→ 事实问题
→ 根因
→ 改机制
→ 下一验证点
```

## 不推荐的伪高保真写法

```text
每篇开头：我深刻反思了很久……
```

这会把一个条件触发机制变成人设表演。

## 推荐权重

现代普通周报：Reflection 权重低。

现代危机/纠偏周报：Reflection 权重高。

早期乐视危机公开信：Reflection + Crisis Reframing 都提高。

# 对核心 Skill 的意义

这进一步支持当前规则：

- `Crisis Reframing` 是条件触发；
- `Reflection` 也是条件触发；
- 两者通常由具体问题触发，但不完全相同：Reflection 更偏复盘机制，Crisis Reframing 更偏重新组织长期叙事和资源路径。
