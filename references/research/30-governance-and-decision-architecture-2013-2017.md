# Research 30 — 2013–2017 治理与决策架构：分布式执行 + 战略拐点集中决断

更新时间：2026-09-03

目的：纠正一种过度简化的描述——“贾跃亭就是高度集权、凡事自己拍板”。公开材料显示，乐视时期更接近一种混合架构：**日常业务和项目执行尽量网络化、项目化、核心团队集体决策；少数非共识战略拐点保留创始人高决断权；关键生态控制点在资本层面尽量不让。**

---

## 1. 2014：从 CEO 主导向核心团队主动创新、集体决策转型

2014 年 9 月内部邮件《乐视为何现在选择全球化》中，贾跃亭明确描述：

- 团队不是“一个人的战斗”；
- 业务决策机制从 CEO 主导生态创新和管理决策，向核心团队主动创新、集体决策转型；
- 组织同时推进“管理型组织 + 项目型组织”；
- 还探索交叉管理、生态决策委员会、生态型考核激励。

这说明至少在公开组织设计上，乐视并不是把所有执行决策都集中到 CEO。

## 2. 2014：生态组织不是普通矩阵，而是“管理线 + 项目线”并行

人民网 2014 年对乐视生态组织的报道提到：

- 组织高度扁平化、网格化；
- 管理型组织与项目型组织并行；
- 生态协同被提升到竞争层级，而不是仅仅作为部门间合作口号。

这类设计背后的逻辑是：传统职能线保证专业能力，项目线保证跨业务目标推进。

可提炼结构：

```text
专业能力线
+
跨生态项目线
+
生态决策/协同机制
```

## 3. 2016：本人明确限定“只有极个别战略拐点由我决定”

2016 年底接受《中国企业家》等采访时，被直接问到“董事会里是不是自己说了算”。贾跃亭回答的核心不是“全部由我决定”，而是分层：

```text
上市体系：按严格规范
战略实现/策略落地：有较严格组织机制
极个别重大拐点：由他最终决定
```

其解释是：真正颠覆性的方向往往不可能靠大多数人投票形成，因此战略方向上的少数非共识判断需要保留集中决断。

来源：

- 界面：https://m.jiemian.com/article/1010881.html

注意：这是一种**本人自我解释**，不能自动等同于治理上的最佳实践。

## 4. 2017：控制权被定义为生态协同的战略控制点

2017 年第一财经专访中，在融资和资本压力背景下，贾跃亭仍明确强调：

- 财务股权可以让出更多；
- 但七个子生态的控制权不愿轻易放弃；
- 原因是任何一个子生态控制权变化都会影响整个生态协同。

这说明其“控制权”偏好并不仅表现为组织权力，更被本人理解为维持长期系统协同的战略工具。

## 5. 更准确的治理模型

综合 2014、2016、2017 三个时间点，可提炼为：

```text
日常执行
→ 尽量项目化 / 网格化 / 核心团队协同

战略实现
→ 专业团队、流程、责任制

重大非共识拐点
→ 创始人保留更高决断权

资本与生态控制点
→ 尽量保留关键控制权
```

这比“创始人中心化”更准确。

## 6. 可用于 Skill 的决策启发式

### G1 — 先分清决策层级

不是所有问题都需要同一种治理方式。

```text
可逆执行决策 → 下放
跨部门复杂决策 → 核心团队
不可逆战略拐点 → 第一责任人承担最终判断
```

### G2 — 战略拐点必须满足更高门槛

只有同时满足以下条件，才允许提高创始人决断权：

1. 问题确实属于长期战略拐点；
2. 决策具有高不可逆性或高时间窗口价值；
3. 团队存在真正信息不对称或路径依赖；
4. 第一责任人承担结果责任；
5. 必须绑定清晰的验证/停止条件。

### G3 — “非共识”不能成为独断的借口

错误形式：

```text
别人反对
→ 所以我更可能正确
```

正确形式：

```text
别人反对
→ 检查是否存在旧范式路径依赖
→ 提出可验证的新假设
→ 小规模验证
→ 再决定是否扩大
```

### G4 — 控制权必须对应真实战略控制点

如果一个资产/平台/入口不是系统关键节点，就不应该因为“控制”本身而牺牲融资效率。

判断：

```text
失去控制权后，是否真的破坏产品、数据、用户或生态协同？
```

如果答案不清楚，就不应把控制权神圣化。

## 7. 对偶风险

这套混合治理最容易出现四个失败模式：

1. **战略拐点定义泛化**：越来越多普通决策被说成“只能创始人判断”。
2. **创始人信息过载**：所有重大事项最终回流到一个人。
3. **集体决策名义化**：团队只能对实现路径负责，不能挑战终局假设。
4. **控制权过度优先**：为了维持系统控制，牺牲融资、治理和专业化速度。

因此 Skill 必须强制加入：

```text
战略拐点
→ 为什么不可逆
→ 为什么不能下放
→ 验证条件
→ 复盘时间
→ 谁能提出终止
```

## 8. 与现代 FF 的连续性

2019 以后 FF 多次出现职业经理人/制造运营负责人承担日常经营，而创始人继续保留产品定义、用户生态和长期愿景角色。2025 回归管理层后，又重新加强创始人模式。

因此跨时期更稳定的模型不是“必须亲任 CEO”，而是：

> **运营角色可以变化，但产品定义、战略终局与关键拐点的创始人控制倾向长期存在。**

---

## 9. Skill 应如何使用

当用户问“贾跃亭会怎么做组织决策”时，不应默认回答“创始人拍板”。

更高保真的顺序：

```text
先判断决策层级
→ 可逆问题下放
→ 跨系统问题核心团队协同
→ 真正战略拐点才提高第一责任人决断权
→ 所有高集中决策绑定验证与退出条件
```

这是国内乐视时期公开资料支持度较高、同时更可执行的治理抽象。
