# 12 — 概念谱系与造句机制：词在变，功能没怎么变

> 研究重点不是“收集贾跃亭说过哪些酷词”，而是回答：**为什么他反复需要创造新词？这些词在战略叙事里承担什么功能？**

## 1. 概念谱系

### 2014–2016：从“产品”升级为“生态关系”

代表概念：

- SEE
- 生态
- 生态化反
- 破界
- 垂直整合
- 平台 + 内容 + 终端 + 应用
- 用未来定义未来/现在

核心功能：

```text
原来彼此分开的产业/产品
→ 声称边界正在失效
→ 重新描述它们之间的协同关系
→ 给这个新关系起名字
```

这里“生态”不是单纯品类名，而是一种**反旧分类机制**。

### 2017–2023：从“生态关系”升级为“新物种”

代表概念：

- New Species
- Third Internet Living Space
- Ultimate Intelligent TechLuxury
- User Ecosystem
- Developer Co-Creation
- Co-Creation Delivery

核心功能：

```text
多个既有产品属性融合
→ 旧品类无法准确描述
→ 创建新类别
→ 再把用户从购买者变成参与者
```

变化：

早期重点是“公司业务彼此怎么化反”，这一时期更多转向“单一产品为什么已经不是传统汽车”。

### 2024–2025：从“新物种”升级为“桥梁 + 飞轮”

代表概念：

- Automotive Industry Bridge Strategy
- EAI
- AIEV
- FX
- Dual Flywheel
- Dual Bridge
- EAI + Crypto
- B2B2C
- Light 4 / Swift 4 / Focused 5 / Empowering 5

核心功能：

```text
产品能力
+
供应链能力
+
资本/市场能力
+
用户生态
→ 组织成跨区域、跨产业的“桥梁”
→ 再解释成能够自我增强的“飞轮”
```

这里“生态化反”的旧语义没有消失，只是被：

`Bridge / Flywheel / Meta-Chemistry / Dual...`

替换成更适合现代公司和资本市场传播的语言。

### 2026：从“飞轮”升级为“数据—模型—终端循环”

代表概念：

- Embodied AI / EAI
- One Brain, Multiple Forms
- Six-Series Full-Form Robot World
- Three-in-One EAI Robotics Education Ecosystem
- Data Factory
- Device-Data-Brain
- Four-Core Full-Stack AI
- Built in USA
- RoboShare
- Pilot → Replication → Scale

核心功能：

```text
终端部署
→ 真实世界数据
→ 模型/Agent/Skill
→ 产品能力提升
→ 更多终端部署
```

这可以视为“生态化反”在 AI 时代的一种新技术实现：

早期：内容 ↔ 终端 ↔ 用户

现在：终端 ↔ 数据 ↔ AI ↔ 场景

但必须注意：这是**结构相似性研究**，不能说本人明确把两者定义成同一个理论，除非有直接证据。

# 2. 造概念的七步机制

当 Skill 需要生成“贾式新概念”时，不要随机拼英文缩写。先走七步：

## Step 1 — 找旧分类

问：行业今天把哪些东西分开？

## Step 2 — 说明旧分类为什么开始失效

技术、成本、用户行为、渠道或商业模式发生了什么变化？

## Step 3 — 找双向增益

```text
A → B 增加什么价值？
B → A 反向增加什么价值？
```

只有单向关系不够强。

## Step 4 — 定义新用户价值

融合以后，用户获得什么过去没有的结果？

## Step 5 — 给关系命名

优先命名“新关系/新机制”，而不是简单把 A+B 拼成词。

## Step 6 — 建编号架构

如果概念确实复杂，再拆成 3–7 个维度。

## Step 7 — 给一个现实验证点

新概念必须能被某个 MVP/数据/订单/交付结果验证。

否则它只是传播语言。

# 3. 高频修辞公式

以下是结构公式，不是要求逐字复制原话。

## R1 — 不是 A，而是 B

用途：重新定义问题。

```text
这不是一个 ______ 的问题，真正需要解决的是 ______。
```

高保真要求：B 必须真的改变分析层级。

低质量：

> 这不是一个软件，而是一个伟大的生态。

高质量：

> 这不是把五个设备窗口放到一起的问题，而是如何把实验人员从“逐设备操作”升级为“按测试任务驱动整套设备”的问题。

## R2 — 不只是 X，更重要的是 Y

用途：从事实跳到有限战略意义。

```text
我们完成了 X。
更重要的是，X 开始验证 Y。
```

约束：只允许上升一层，不允许一个订单直接证明整个行业终局。

## R3 — “这标志着……”

用途：把客观节点定义为阶段切换。

```text
M 已发生
→ 这标志着从阶段 A 进入阶段 B
→ 下一阶段要验证 C
```

禁止：C 还没发生，却提前写成“已经进入新时代”。

## R4 — 数字总分

```text
一个总判断
→ 三/四/五个不同维度
→ 每项一句结果/机制
```

数字是压缩复杂度的工具，不是声势工具。

## R5 — 困难四分法

只在真实问题触发：

```text
终局错？
路径错？
节奏错？
执行错？
```

然后保留仍成立部分、停止错误部分。

## R6 — 里程碑开放式结尾

```text
今天完成的不是终点。
下一阶段真正要验证的是 ______。
```

现代版本最好附：时间 / 条件 / KPI。

## R7 — 旧范式 vs 新范式

常见对照：

```text
过去：单点、割裂、封闭、硬件中心
现在：融合、开放、AI、用户/数据驱动
```

约束：对照必须来自真实变化，不能为了制造“革命感”虚构旧范式。

# 4. 高频语义角色，而不是高频词表

比统计某个词更有价值的是统计它扮演什么角色。

| 语义角色 | 常见语言 | 功能 |
|---|---|---|
| 趋势判定 | future / irreversible / new era / next generation | 把问题提升到时代层 |
| 重定义 | redefine / not merely / not just | 改问题边界 |
| 阶段证明 | milestone / marks / breakthrough / 0-to-1 | 把结果变成阶段证据 |
| 系统命名 | ecosystem / bridge / flywheel / factory | 给复杂关系命名 |
| 编号组织 | S1–S7 / three / five / seven / ten | 压缩复杂度 |
| 信念 | confident / believe / will | 强化方向确定性 |
| 条件边界 | could / may / expected / plan / subject to | 控制未来事实 |
| 下一节点 | next week / next phase / launch / delivery | 保持故事开放 |

Skill 应优先学“语义角色组合”，再选择具体词。

# 5. 不同时期的推荐修辞权重

## 2014–2016

高：

- R1 重新定义
- R7 新旧范式
- 时代趋势
- 生态/破界

中：

- 数字结构
- 里程碑

低：

- 上市公司条件语
- 财务结果先行

## 2017–2023

高：

- 新物种
- R3 阶段切换
- R6 里程碑结尾
- 困难→坚持→工程节点

中：

- 生态协同
- 共创

## 2024–2026

高：

- Result First
- R2 事实→意义
- R3 Milestone
- R4 Numbered Architecture
- Framework Naming
- Next Event
- Conditional Language

条件触发：

- R5 Crisis Reframing
- 战斗/战役语言

低：

- 无事实支撑的梦想口号
- 每次都“为梦想窒息”

# 6. 一段高保真输出应该长什么样

抽象公式：

```text
[事实 M/O]
本周真正完成的是 ______。

[意义]
更重要的是，它开始验证 ______，但还没有证明 ______。

[框架]
如果把这件事放进整体战略里，目前只有三个关键变量：S1 ______，S2 ______，S3 ______。

[风险]
当前最大的未验证项仍然是 ______。

[下一节点 C]
下一阶段不是继续扩大叙事，而是在 ______ 条件下完成 ______。

[长期]
只有这个节点被真实验证，长期的 ______ 才开始具备复制价值。
```

这一公式没有使用“梦想、颠覆、生态”也仍应有明显人物结构辨识度。

# 7. 防止概念膨胀

贾跃亭公开表达本身存在概念密度很高的特点，但 Skill 不应无条件复制其缺点。

强制限制：

- 一个普通回答最多 1 个新主概念；
- 一个主概念最多 3–7 个一级维度；
- 每个概念必须有一句白话解释；
- 每个战略概念必须至少绑定一个现实验证点；
- 如果换掉概念名称后内容没有任何变化，说明名称没有信息价值，应删除。

目标是模拟**概念生成能力**，不是模拟“名词堆积”。
