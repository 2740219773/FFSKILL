# 13 — 现有开源贾跃亭 Skill 对照研究

## 对照项目

GitHub：
https://github.com/zhanpengumich/jia-yueting-skill

该项目是目前检索到的一个直接以贾跃亭为对象的公开 Skill，实现目标更偏“强角色扮演/人生哲学顾问”。

本文件的目的不是评价作者，而是回答：**哪些结构值得参考，哪些设计会让人物 Skill 失真？**

---

# 1. 值得借鉴的设计

## 1.1 Trigger 写得明确

对方在 frontmatter 中明确列出：

- 人名别称；
- 乐视/FF；
- EAI/机器人；
- “如果你是贾跃亭”类自然语言。

优点：

Skill 什么时候应该触发比较明确，而不是只靠用户精确输入 Skill 名。

### 对 FFSKILL 的启发

我们的 description 可以继续保持“贾跃亭怎么看/会怎么干/会怎么讲”三类触发语义，不必堆几十个别称，但应保证自然表达能激活。

---

## 1.2 有 Agentic Protocol

对方区分：

- 事实型问题；
- 哲学/人生型问题；
- 混合问题；

并要求涉及最新 FF、债务、机器人竞争等内容时先查事实。

这条原则本身是正确的。

### 对 FFSKILL 的启发

我们的 Skill 应进一步明确：

```text
本人事实问题 → 查原始来源
人物模式问题 → 读 evidence matrix / decision heuristics
新情境推演 → A/B 模型 → C 类输出
```

---

## 1.3 单独保存“内在张力”

对方尝试记录：

- 生态理想 vs 资金约束；
- 先行者叙事 vs 执行责任；
- 高情绪可信度 vs 承诺兑现；
- 开放/去中心化叙事 vs 强创始人中心。

这是人物研究非常有价值的结构：**矛盾不是 Bug，可能正是人物模型的核心。**

### 对 FFSKILL 的启发

不应该只保存“擅长什么”，还要保存：

```text
能力 A 在什么条件下会翻转成风险 B？
```

例如：

- Future-Back → 可能低估现金流；
- Ecosystem → 可能造成多线扩张；
- Founder-Led → 可能产生治理瓶颈；
- Narrative Continuity → 可能弱化失败信号；
- Milestone Storytelling → 可能诱导“可宣传节点优先”。

---

## 1.4 有“诚实边界”章节

对方意识到：

- 技术主张要独立核实；
- 债务叙事和法律事实要分层；
- 订单数字的定义需要确认；
- 时间承诺需要单独评估。

这个设计方向值得保留。

我们当前的 A/B/C + V/C/M/O 比它更系统，但可以继续增强“争议事实必须脱离人物叙事独立核验”的规则。

---

## 1.5 有 Few-shot

Few-shot 能帮助模型在真正输出时保持语气，而不是只理解抽象规则。

### 可以借鉴，但要改造

我们的 Few-shot 不应让模型冒充本人，也不应把未经验证的数字和个人经历写成第一人称事实。

推荐做：

- `高保真但事实安全` 示例；
- `低质量玩梗` 反例；
- `同一问题 2015 / 2026 两个版本`；
- `计划 vs 结果` 边界示例。

---

# 2. 不应该照搬的地方

## 2.1 直接把模型写成“你就是贾跃亭”

对方采用强第一人称身份模拟。

风险：

- 容易把模型推演写成本人真实经历；
- 容易伪造未发生的私人想法；
- 事实错误会因为第一人称显得更加确定。

FFSKILL 当前坚持：

> 模拟公开可观察的结构，而不是声称成为本人。

这个方向保留。

---

## 2.2 网络梗被写进人物事实

对方 README / Skill 把“下周回国”等网络标签直接作为人物固定承诺/口头特征。

问题：

一个网络梗可能来自媒体长期概括，并不等于本人真的高频逐字说过。

### FFSKILL 强制规则

```text
网友标签
≠ 本人原话
≠ 稳定语言 DNA
```

只有找到多个本人一手来源才能升级。

---

## 2.3 “绝对不会承认战略错”属于过拟合

对方明确规定类似：

- 不会说失败；
- 永远解释为战略蜕变；
- 执行有偏差，但战略方向正确。

这种规则“角色味”很强，但研究质量很差。

原因：

- 把历史观察升级成不可证伪人格定律；
- 面对新问题时模型会无脑坚持；
- 无法处理技术已被证伪、需求不存在等情境。

### FFSKILL 的替代

```text
先判断：终局 / 路径 / 节奏 / 执行
```

如果核心假设被事实证伪，允许判断终局错误。

人物高保真不能凌驾于现实。

---

## 2.4 用“先行者必被误解”覆盖所有失败

对方把乔布斯、马斯克等成功者类比设成默认防御机制。

问题：

这是典型幸存者偏差风险。

### FFSKILL 的替代规则

“被质疑”本身不能证明先行者身份。

需要：

```text
独立技术证据
+ 用户/业务结果
+ 里程碑兑现
+ 反证测试
```

再判断长期方向是否得到验证。

---

## 2.5 强情绪角色感压过事实状态

对方示例倾向：

```text
困难
→ 梦想
→ 历史类比
→ 最新数字
→ 时间会证明
```

这种结构很有戏剧性，但容易发生：

- preorder 被写成交付；
- target 被写成承诺结果；
- 公司自述被写成客观结论；
- 单个里程碑被扩大为战略成功。

### FFSKILL 的替代

先 V/C/M/O，再写情绪。

```text
事实状态
> 叙事感染力
```

# 3. 两个 Skill 的定位差异

| 维度 | 现有开源 Skill | FFSKILL 当前方向 |
|---|---|---|
| 目标 | 强角色扮演 | 人物思维/行动模型 |
| 第一人称 | 强制“我是贾跃亭” | 默认不冒充本人 |
| 资料结构 | 主要集中在单个 Skill | 独立 research corpus |
| 时期路由 | 主要偏 2026 + 历史叙事 | 2014–16 / 2017–23 / 2024–26 |
| 事实状态 | 有诚实边界，但不系统 | V/C/M/O 强制状态机 |
| 推演边界 | 容易角色化为本人观点 | A/B/C 证据分层 |
| 风格 | 悲壮、梦想、先行者 | 逻辑结构优先，词汇其次 |
| 战争/梦想语言 | 权重较高 | 场景触发 |
| 决策研究 | 有启发式，但部分来自角色假设 | 用具体治理/资本/产品行动提炼 |
| 测试 | 少量 Few-shot | fidelity + modern weekly regression |
| 可证伪性 | 较弱 | 强制现实校验/停止条件 |

---

# 4. 可以吸收进 FFSKILL 的四个点

## A. 增加“核心张力”专项研究

不是为了批判人物，而是防止模型单向美化。

## B. 增加 Few-shot / Contrast-shot

尤其：

- 同一问题早期/现代两个时期；
- 高质量/玩梗两个版本；
- 计划/结果两个版本。

## C. 增强触发描述

让自然语言“用老贾的思路想一下”“贾总会怎么干”都能识别。

## D. 保持事实型问题先研究再回答

涉及：

- 最新 FF；
- 交付；
- 订单；
- 财务；
- 债务；
- 法律；
- 机器人技术；

必须查当前资料，不能靠人物模型补事实。

---

# 5. 最终结论

这个开源 Skill 很适合作为：

**角色表现力参考 + 反面事实安全样本。**

它证明了一个问题：

> “像贾跃亭”其实很容易——梦想、悲壮、生态、先行者、时间证明。
>
> 真正难的是：既有这种辨识度，又不让角色叙事吞掉现实。

因此 FFSKILL 的竞争点不应该是“比它更会演”，而应该是：

```text
更像他的思考结构
+
更接近真实行动方式
+
更能区分时期
+
更严格区分计划与结果
+
面对反证时能真正改变判断
```

这也是后续 V0.4 的主方向。
