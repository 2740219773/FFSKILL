# Research 34 — 乐视组织操作系统：分布式执行 + 少数拐点中心化

更新时间：2026-09-03

## 核心结论

把国内时期贾跃亭简单概括为“独断”或“扁平化”都不准确。

2014–2016 的一手/近一手资料更接近一种张力结构：

```text
日常执行 / 跨部门项目
→ 尽量扁平化、网格化、项目 Owner 化

极少数战略重大拐点
→ 创始人保留更高最终决断权
```

可以暂命名为：

**Distributed Execution + Centralized Inflection**

这不是价值判断，而是公开资料中可观察到的组织设计偏好。

# 1. 2014：生态战略先逼组织变形

2014 新年信直接提出：

```text
生态型业务
→ 必须匹配生态型组织
```

本人已经意识到：

- 生态链变长；
- 部门变多；
- 专业化分工会产生部门墙；
- 协同失败会让系统内耗。

因此组织变革不是 HR 优化，而被视作战略必要条件。

---

# 2. 两套并行组织

2014 公开报道记录乐视推行：

## 管理型组织

强调：

- 扁平化；
- 交叉管理；
- 日常管理；
- 快速决策。

## 项目型组织

强调：

- 网格化；
- 结果导向；
- 打破职级；
- 每个跨产业链项目提炼 1–2 个真正负责人。

公开材料甚至描述：项目型组织里 VP 可能向项目负责人汇报。

### 底层意图

```text
纵向专业能力
+
横向用户结果
```

试图同时保留。

这和 2015“开放闭环”的第三范式思维很相似：不是传统职能制 A，也不是完全项目制 B，而是 A+B 的新组织组合。

但这种组合是否真的解决矛盾，需要靠权责设计证明。

# 3. 2014 全球化邮件：CEO 主导并不是理想终态

2014 年内部邮件里，本人称业务决策机制正在：

```text
CEO 主导生态创新和管理决策
→ 核心团队主动创新、集体决策
```

同时提到：

- 管理型/项目型并行；
- 交叉管理；
- 生态决策委员会；
- 生态型考核激励。

这条证据非常重要，因为它反驳一种过度简化：

> “贾跃亭的管理哲学就是所有事情自己说了算。”

至少在公开组织设计中，他曾明确把“团队集体决策”当作组织成熟方向。

---

# 4. 2016：本人承认双组织的真实副作用

在危机期长访谈中，记者直接问生态组织是否会导致：

- 部门交叉太多；
- 权责划分不清晰。

本人回答：会。

并进一步解释：

- 交叉管理会有两个或更多领导；
- 项目组织交叉点更多；
- 第一责任与协同责任需要排序。

这是非常有价值的 A 类反证：

> 组织理论发明者本人承认它存在结构性协调成本。

---

# 5. 2016：极少数战略拐点又回到中心化

同年的 43 问中，本人进一步区分：

```text
上市体系：严格按治理规范
战略实现/策略落地：严格机制
非上市体系极个别重要拐点：由他决定
```

其理由是：真正的颠覆性方向往往不是多数人共识。

于是完整结构变成：

```text
执行层：分布式/项目化/协同
多数业务决策：团队化
极少数战略拐点：创始人中心化
```

这比“Founder-Led”更准确。

---

# 6. 为什么这个模型可能有效

适合以下场景：

- 跨专业复杂产品；
- 多部门共同交付一个用户结果；
- 传统部门边界会阻碍创新；
- 核心战略确实存在非共识选择。

优点：

- 产品跨部门速度快；
- 用户结果不容易被职能 KPI 切碎；
- 战略转向可避免委员会平均主义；
- 创始人的长期判断能够保持一致。

---

# 7. 为什么它也容易失败

## 7.1 多领导

矩阵组织最直接的问题：一个人多个领导、多个优先级。

## 7.2 责任扩散

“大家协同”如果没有唯一结果 Owner，会变成“所有人负责 = 没人负责”。

## 7.3 创始人成为最终冲突处理器

交叉点越多，若缺少明确规则，冲突最终全部升级到创始人。

## 7.4 “重大拐点”定义膨胀

如果创始人把越来越多问题定义成“战略拐点”，组织会重新退化成高度中心化。

# 8. Skill 中的正确实现

## 日常执行

```text
一个用户结果
→ 一个最终 Owner
→ 多专业资源虚拟组队
→ 职能线保证专业质量
→ 项目线保证交付
```

## 冲突处理

必须预先定义：

- 优先级归谁决定；
- 多领导冲突多久内升级；
- 哪类决策项目负责人能自行拍板；
- 哪类必须回职能线；
- 哪类才属于战略拐点。

## 战略拐点

只有满足至少三项才升级 Founder Inflection：

1. 改变公司类别；
2. 改变核心盈利模式；
3. 改变关键控制权；
4. 改变长期资源配置；
5. 一旦决定很难逆转。

然后必须绑定：

- 风险预算；
- 证伪实验；
- 独立专家意见；
- 董事会/合规边界；
- 明确责任。

---

# 9. 与现代 FF 的潜在连续性

现代 S1–S7 / Weekly Report 可以看作另一种实现方式：

```text
早期：矩阵/项目组织 + 周会/协同会
→
现代：编号战役 + Owner/KPI + 固定周报
```

现代方法更显式、更容易审计，但是否真正解决组织复杂度仍需用实际结果验证。

---

# 一句话模型

> **让执行尽可能分布式，让极少数真正不可逆的战略拐点保持强中心决断；但必须防止“重大拐点”定义膨胀。**
