# Methodology — 人物 Skill 提炼方法

本项目的方法参考了开源项目 `alchaincyf/nuwa-skill` 的人物思维蒸馏思路，并结合贾跃亭材料的特殊性增加了：跨时期验证、语言/行动分离、承诺结果状态机和上市公司条件语校验。

参考项目：`https://github.com/alchaincyf/nuwa-skill`

## 1. 一个特征什么时候可以进入核心 Skill

不是“看起来很像”就可以。至少经过以下四项检查。

### 1.1 跨时期复现

同一模式至少在两个不同时间点出现。

更高置信度标准：

- 乐视时期出现；
- FF 长周期出现；
- 2024–2026 仍出现。

例如“新物种/重新定义”从乐视汽车、FF91 到 EAI/机器人持续出现，置信度高。

### 1.2 跨场景复现

同一模式不能只出现在一类发布会。

更强证据包括它同时出现在：

- 产品定义；
- 组织管理；
- 危机沟通；
- 资本市场；
- 工程里程碑；
- 全球化战略。

例如数字化架构不仅用于产品发布，也用于“十大变革、S1–S7、七大战役”的经营管理，因此比普通演讲排版更值得进入 Skill。

### 1.3 有生成力

这个模型应能帮助推演新问题。

例如 Future-Back 如果是真模型，那么面对“做实验室上位机”时，应自然推导出：

```text
先定义未来实验人员完整工作流
→ 找设备软件孤岛边界
→ 重构为统一状态/流程/数据闭环
→ 再倒推 MVP
```

如果一个特征只能解释历史，无法生成新判断，它更适合作为人物资料，而非核心模型。

### 1.4 有区分度

“重视用户”“努力奋斗”“关注创新”太通用，不应单独成为人物模型。

更有区分度的组合是：

```text
未来终局
+ 破界
+ 新命名
+ 数字架构
+ 高信念
+ 里程碑传播
+ 危机叙事连续
```

人物辨识度往往来自多个模型的组合，而不是单个口号。

## 2. 模型置信度

### A — 核心稳定模型

满足：

- 跨时期；
- 跨场景；
- 有生成力；
- 有区分度；
- 最好同时有语言和行动证据。

可进入 `SKILL.md` 主干。

### B — 阶段增强模型

某一阶段反复出现，但不能证明全时期稳定。

例如：

- 2025–2026 战争隐喻明显增强；
- 股东优先、Performance-Is-King 属于上市公司后期强化层；
- AI 作为统一底座属于新时期特征。

应通过“时期路由”启用，不可倒灌到 2015 年。

### C — 单点特征

只在一次采访/事件中出现。

保存到 research，但不进入核心规则。

## 3. 语言和行动必须分离记录

每个重要案例应至少记录四层：

```text
公开说法：他说了什么
公开目标：承诺/预计什么
实际动作：真正做了什么
实际结果：最终发生了什么
```

原因：

- 说“聚焦”不等于资源一定已经聚焦；
- 说“交付目标”不等于已经交付；
- 说“生态协同”不等于组织中真的产生协同。

因此人物语言模型和人物决策模型不能直接互相替代。

---

## 4. V/C/M/O 状态标注

研究重大项目时，每条信息标注：

- `V` Vision：愿景；
- `C` Commitment/Target：承诺、计划、目标；
- `M` Milestone：客观完成的中间节点；
- `O` Outcome：用户/业务实际获得的结果。

示例：FF91

```text
V：定义新的智能电动车物种
C：某阶段计划在某时间开始生产/交付
M：白车身、预量产车、SOP、首台量产车下线
O：正式交付外部用户并进入实际使用
```

任何研究摘要禁止把 C 写成 M/O。

---

## 5. 表达 DNA 的量化计划

参考人物 Skill 蒸馏方法，后续对足够长的原始语料进行统计，而不是全靠主观感觉。

建议按三个时期分别抽取至少 20 个长段落：

- 2014–2016；
- 2017–2023；
- 2024–2026。

统计：

| 维度 | 指标 |
|---|---|
| 句长 | 平均字数/句，中位数 |
| 第一人称 | “我/我们”频率 |
| 确定性 | 一定、必然、真正、不可逆 vs 可能、预计、计划 |
| 转折 | 但是、而、真正、不是…而是… |
| 战略放大 | “意味着/标志着/验证/新阶段”频率 |
| 数字结构 | 三大/五大/S1 等编号密度 |
| 战争隐喻 | 战役、进攻、fight、win 等 |
| 新概念密度 | 每千字新命名数量 |
| 事实数据密度 | 数字/KPI/交付数据每千字 |
| 条件语 | 预计、目标、subject to、if 等 |

目标不是追求学术统计精度，而是判断“时期演化”和“哪些直觉是真的”。

## 6. 矛盾不要抹平

### 6.1 时间性矛盾

早期和后期表达不同。

处理：时期路由，而不是选一边当作永恒人格。

### 6.2 理念与执行张力

例如：

- 生态协同 vs 组织复杂度；
- 高信念 vs 现金流约束；
- 战略完整性 vs 短期融资效率；
- 创始人深度介入 vs 公司治理；
- 里程碑传播 vs 承诺延期。

这些张力本身应进入模型，而不是被“人物粉丝化”消除。

### 6.3 本人解释与第三方事实冲突

并列保存：

```text
本人解释：...
公司正式披露：...
第三方/监管材料：...
可确认事实：...
仍有争议：...
```

## 7. 反证优先规则

每次想把一个新特征升级为核心模型，主动搜索：

1. 有没有完全相反的公开表达？
2. 有没有行动与说法明显不一致？
3. 这个模式是否只是一段时期的公关语言？
4. 是否所有科技企业家都会这么说？
5. 是否存在失败案例可以界定它的边界？

如果反例很多，降级为阶段特征。

---

## 8. 原始来源优先级

从高到低：

1. 本人完整讲话/公开信/微博/视频；
2. FF/乐视正式材料；
3. 监管/证券文件；
4. 完整采访；
5. 权威媒体深度报道；
6. 前员工/合作方回忆；
7. 普通评论和社区讨论。

社区梗只用于研究公众印象，不允许直接变成“本人语言 DNA”。

---

## 9. 进入 Skill 的压缩规则

Research 可以很长，但核心 Skill 不应无限增长。

每个核心模型只保留：

```text
模型名称
→ 核心逻辑
→ 触发场景
→ 执行步骤
→ 现实边界
```

历史证据保留在 `references/research/`。

当同类材料越来越多，不继续往 `SKILL.md` 堆案例，而是提高模型置信度。

---

## 10. 质量目标

最终应达到：

- 删除人物名字仍有明显独特思维结构；
- 用它回答一个从未谈过的新问题，仍能产生有价值视角；
- 不需要堆“颠覆/生态/梦想”也有辨识度；
- 对失败、延期、财务约束保持事实感；
- 能区分 2015 和 2026 的语言变化；
- 能同时呈现能力与代价，而不是粉饰或恶搞。
